## 1. Professor's Requirements Specification (Quoted Verbatim)

1. Have slices.
2. Number of CRUD operations = number of repositories x 4.
3. Create slices based on repositories and have CRUD operations using reducers.
4. Any data being displayed in a component must be displayed from the Redux store.
5. When we move between components the state should clear (the professor is NOT SURE about this one).
6. Use THUNK to synchronise between front end and back end.
7. No local storage. State must be maintained in variables.
8. Stores must be present with slices, showing how we put the roles and controllers, CRUD slices, and all displayed data must come from the Redux store.
9. Follow the THUNK pattern.

*(Note: Because of Requirements 6 and 9, the conversion targets **Redux Toolkit** using `createSlice`, `createAsyncThunk`, and optional `createEntityAdapter`, without RTK Query or external fetching libraries.)*

## 2. Counting `N` (Repositories) and `4 x N`

### Architectural Asymmetry in TeamForge Back End
The NestJS back end stores in-memory data using **four different patterns** rather than a single `*.repository.ts` convention:
1. **Explicit `*Repository` classes** (9 files / 9 classes, holding 10 arrays — `MentorshipRepository` holds 2 distinct arrays).
2. **`BaseService<T>` subclasses** (`back-end/src/common/abstracts/base.service.ts:4-46`) that extend a generic in-memory array store `protected readonly items: T[] = []` directly (6 services).
3. **Domain Entity Services** that store private entity arrays/Maps/singletons directly on `@Injectable()` services (e.g., `NotificationsService`, `ReportsService`, `AuditService`, `JobRunsService`, `MentorMarketplaceService` holding 8 distinct entity arrays).
4. **Backend Internal-Only Token, Digest, Log, and Payment/Idempotency Stores** (`DemoUpiProvider`, `DigestService`, `AuthService` token lists, `UsersService.otpChallenges`, `LogManagerService`).

*(Not counted as repositories: ephemeral security/runtime guards such as `RateLimiterMiddleware.requestMap`, `LoginThrottleService` sliding-window maps, `FirebaseStrategy.tokenCache`, `LeaderboardService.cachedLeaderboards` TTL cache, per-project/session promise queues, `DemoResetService.resetTimestamps`, `VisitorRateBuckets`, `AccountDeletionService.deleteAttempts`, and `UsersService.phoneVerifyAttempts`.)*

Because Requirement 2 specifies `CRUD operations = number of repositories x 4`, we record **both** exact counts transparently and raise the choice for professor sign-off in [`questions.md`](./questions.md):

| Counting Basis | `N` (Total) | `4 x N` (Total CRUD Ops) | `N_ui` (FE-Used) | `4 x N_ui` (UI CRUD Ops) | Architectural Trade-off |
|---|---:|---:|---:|---:|---|
| **Lens A: Literal `*Repository` classes only** (`class *Repository`) | **9** | **36** | **8** | **32** | Excludes `Notifications`, `JoinRequests`, `Reports`, `Appeals`, `MentorMarketplace`, `Support`, `Escrow`, `Audit`, `JobRuns`, etc. Violates Req. 4 unless those screens stay outside Redux. |
| **Lens B: All logical domain entity collections / stores** *(Recommended for complete Req. 4 & 8 compliance)* | **41** | **164** | **31** | **124** | Covers every in-memory collection across `*Repository` (10), `BaseService` (6), Domain Services (20), and Internal-Only Stores (5). Zero displayed server data left out of Redux. |

**Missing `docs/` artifacts noted:** `docs/work-division.md`, rubric evidence docs, and prior `docs/redux*` docs were **not found** in the repository (`PROGRESS.md` is at repo root, not `docs/PROGRESS.md`).

## 5. Identified Gaps & Architectural Decisions (Do Not Invent Endpoints)

1. **Unwired Front-End Endpoints (`adminApi.js` & `AdminReports.jsx`):**
   - `adminApi.getNeedsReviewSessions()` (`GET /admin/mentor-sessions/needs-review`) and `adminApi.clearSessionReview()` (`POST /admin/mentor-sessions/:sessionId/clear-review`) are called in `React-Implementation/React-Implementation/src/pages/admin/AdminReports.jsx:153-154, 174-175, 193-202`, **but neither route exists in any backend controller** (`MentorMarketplaceService.clearSessionReview` exists at `mentor-marketplace.service.ts:4677` without a controller handler).
   - **Decision:** Keep thunks typed cleanly to handle HTTP 404 gracefully (as existing code does with `.catch(() => [])`) and ask whether to wire those 2 backend controller endpoints or remove dead FE calls.
2. **Missing REST CRUD Endpoints on Append-Only / Scoped Repositories:**
   - Do **not** fabricate fake HTTP routes for `DELETE /audit`, `DELETE /reports`, `DELETE /reputation`, `DELETE /communication/messages/:id`, or `GET /tasks` (unscoped). Where Requirement 3 asks for CRUD reducers (`setAll`/`addOne`/`updateOne`/`removeOne`), define the four synchronous reducers on every entity slice while wiring `createAsyncThunk` **only** to HTTP endpoints that actually exist (see [`05-thunk-pattern.md`](./05-thunk-pattern.md)).
3. **Consolidated Slice Grouping vs. 1:1 Collection Mapping:**
   - Strictly 1:1 across FE-used collections yields **31 domain collections** (plus `session` & `ui`). A cleaner architectural grouping keeps **`mentorAbandonmentHistory`** inside `sessionFeedbacks` (since it only arrives bundled in `GET /admin/mentors/:id/feedback`) and **`audit/adminStats`** cleanly scoped, yielding **28–30 domain slices** — we analyze this exact choice in [`03-requirement-interpretation.md`](./03-requirement-interpretation.md) and [`07-conversion-plan.md`](./07-conversion-plan.md).
